Mogli - Tempelflucht 2.2.1
==========================

Ein Jump'n'Run fuer den Browser. Ein Knopf, immer nach oben.
A browser platformer. One button, always upward.


DEUTSCH
-------

INSTALLIEREN

  1. Diese ZIP-Datei auf deinem Webspace entpacken, zum Beispiel nach
     /public_html/mogli/
  2. Im Browser aufrufen: https://deine-domain.tld/mogli/

  Mehr ist nicht noetig. Es gibt keine Datenbank, keine Installation, keine
  Konfiguration.

WICHTIG: NICHT PER DOPPELKLICK OEFFNEN

  Das Spiel besteht aus JavaScript-Modulen. Browser laden die aus
  Sicherheitsgruenden nicht ueber file:// - ein Doppelklick auf index.html
  zeigt eine leere Seite. Es braucht immer einen Webserver. Zum Ausprobieren
  auf dem eigenen Rechner genuegt im entpackten Ordner:

      php -S localhost:8000
      python3 -m http.server 8000

SO WIRD GESPIELT

  Es gibt genau einen Knopf: die Spielflaeche selbst. Tippen oder klicken.

  1. Mogli steht still, bis du das erste Mal tippst. Erst dann laeuft er los,
     und erst dann steigt die Glut. Du bestimmst, wann es losgeht.
  2. Er laeuft von allein. Es gibt keine Richtungstaste.
  3. Tippen springt. Immer gleich hoch. Es gibt keinen Doppelsprung.
  4. Laeuft er am Boden gegen eine Wand, dreht er von selbst um.
  5. Rutscht er an einer Wand ab, stoesst ihn ein Tipp weg - und ab da laeuft
     er in die andere Richtung. Das ist der Kern des Spiels. Es gibt genau
     EINEN Wandsprung je Flugphase; zurueck bekommst du ihn beim Landen und
     wenn dich eine Ranke hochreisst.
  6. Smaragde geben Punkte. Ranken reissen ihn ein gutes Stueck nach oben.
  7. Von unten steigt die Glut. Wer stehen bleibt, wird geholt.

  Am Rechner geht auch: Leertaste springen, P Pause, R neu starten,
  M Ton an/aus, F Vollbild. Gamepads werden unterstuetzt.

  Auf dem Handy fuellt das Spiel den Bildschirm: die Seite ist genau so hoch
  wie das Fenster, es gibt nichts zu scrollen, und beim Start geht es von
  allein ins Vollbild. Die Bestenliste steht im Menue und nach jedem Lauf im
  Ergebnis - sie liegt ueber dem Spiel, nie darunter.

EIGENE GRAFIK EINSETZEN

  Unter /admin kannst du eigene Bilder einsetzen, ohne Code anzufassen:
  die Figur (acht Bewegungen mit je fuenf Bildern), die Kacheln und den
  Hintergrund. Zugangscode ist 6713.

  GROESSE UND FORMAT SIND EGAL

  Du musst nichts zurechtschneiden. PNG, JPEG, WebP, GIF - was der Browser
  lesen kann, geht, und in jeder Groesse. Der Admin-Bereich rechnet um:

    - Figur  -> 32 x 32
    - Kachel -> 16 x 16
    - Ebene  -> so gross, dass sie den Bildschirm deckt

  Das Seitenverhaeltnis bleibt dabei erhalten - ein breites Bild wird nicht zum
  Quadrat gezerrt, sondern eingepasst. Ob dabei geglaettet wird, entscheidet
  sich von selbst: geht das Verhaeltnis glatt auf (64 -> 32), bleiben die
  Pixelkanten scharf; geht es krumm auf (100 -> 32), wird geglaettet, weil
  sonst ganze Zeilen wegfielen. Nach jedem Einsetzen steht unten, was passiert
  ist.

  Ein sehr hohes Bild als Hintergrundebene wird mittig beschnitten und
  notfalls weiter verkleinert - nicht aus Prinzip, sondern damit das ganze
  Paket noch durch den PHP-Upload deines Webspace passt.

  HINTERGRUND: DAS TEMPO ENTSCHEIDET ALLES

    Tempo 0     Das Bild steht still. Es fuellt den ganzen Bildschirm und wird
                mittig beschnitten, wo das Seitenverhaeltnis nicht passt. Das
                ist die Einstellung fuer ein Hintergrundbild.
    Tempo > 0   Die Ebene laeuft beim Klettern mit. Sie wird auf die Breite des
                Spiels gezogen und untereinander wiederholt; ihre Hoehe sagt,
                nach welcher Strecke sich das Muster wiederholt. 1 wandert
                genauso schnell wie der Turm.

  AM SCHNELLSTEN MIT GIF

  Neben jeder Bewegung sitzt ein GIF-Knopf. Ein animiertes GIF dort hineinlegen
  fuellt alle fuenf Plaetze auf einmal - kein Einzelnes-Bild-Exportieren, keine
  vertauschte Reihenfolge. Das GIF muss 32x32 gross sein.

    - mehr als fuenf Bilder: fuenf davon werden nach ihrer Laufzeit im GIF
      ausgewaehlt, ein lange stehendes Bild bekommt also mehr Plaetze
    - weniger als fuenf: sie werden auf die fuenf Plaetze verteilt, keines
      faellt weg
    - was passiert ist, steht danach als Meldung da

  Das GIF wird dabei im Browser zerlegt; auf den Server gehen weiterhin nur
  die fuenf einzelnen PNG. Einzelne Plaetze nehmen wie bisher PNG.

  WICHTIG, BITTE EINMALIG AENDERN:
    - In admin.php die Zeile ADMIN_CODE auf ein laengeres Wort setzen.
      Vier Ziffern sind 10 000 Moeglichkeiten. Es gibt zwar eine Bremse
      (fuenf Versuche je zehn Minuten), aber ein laengeres Wort ist der
      einzige wirkliche Schutz. Die Zeile nimmt jede Zeichenkette.
    - In admin.php die Zeile ADMIN_SALT auf beliebigen Zufallstext setzen.

  Im Reiter "Vorschau" spielt ein Automat dein Spiel mit deinen Bildern.
  Kommt er nicht mehr vom Fleck, ist der Turm mit deinen Kollisionskaesten
  nicht mehr besteigbar - dann lieber nochmal nachbessern.

  Ohne PHP geht es auch: dort bleibt alles in deinem Browser, und der Knopf
  "Als Datei laden" gibt eine assets.json heraus, die du selbst nach data/
  hochlaedst.

WELTWEITE BESTENLISTE

  Liegt score.php mit auf dem Server und ist PHP aktiv, tragen sich alle
  Spielenden in eine gemeinsame Bestenliste ein. Gespeichert wird in einer
  einfachen Datei unter data/scores.json - keine Datenbank noetig.

  Zu tun:
    - Das Verzeichnis data/ muss fuer PHP beschreibbar sein:
          chmod 755 data
      Manche Hoster verlangen 775 oder einen bestimmten Besitzer.
    - In score.php ganz oben RATE_SALT auf einen beliebigen eigenen Zufallstext
      aendern. Er sorgt dafuer, dass IP-Adressen nur als Hashwert gespeichert
      werden.

  Kein PHP vorhanden oder data/ nicht beschreibbar? Dann laeuft das Spiel
  trotzdem vollstaendig. Die Bestenliste schaltet automatisch auf "Nur auf
  diesem Geraet" um und speichert im Browser. Im Spiel steht sichtbar, welcher
  Modus gerade laeuft.

  Bei nginx statt Apache greift die mitgelieferte data/.htaccess nicht. Dort
  gehoert in die Serverkonfiguration:

      location ~ /data/ { deny all; return 404; }

  Wer die Punktestaende lieber ganz ausserhalb des Webverzeichnisses ablegt,
  setzt in score.php die Konstante DATA_DIR auf einen absoluten Pfad.

EHRLICH GESAGT

  Die Punkte werden im Browser der Spielenden berechnet. Wer will, kann mit
  einem einzigen Kommandozeilenaufruf eine erfundene Zahl schicken. score.php
  weist unsinnige Werte ab, begrenzt die Eintraege pro IP und laesst keine
  HTML-Zeichen in Namen zu - aber gegen jemanden, der es wirklich darauf
  anlegt, hilft das nicht. Die Liste ist zum Spass da, nicht als Urkunde.

NEUE FASSUNG HOCHGELADEN UND ES SIEHT AUS WIE VORHER?

  Oder schlimmer: das Menue steht da, aber auf "Los geht's" passiert nichts.

  Das ist fast immer der Zwischenspeicher des Browsers. Er hat die alte
  index.html behalten und laedt dazu neuen Code - oder umgekehrt. Die beiden
  passen dann nicht zusammen, und das Spiel bleibt stumm im Menue stehen.

  Zu tun:
    1. Wirklich ALLE Dateien ersetzen, nicht nur die geaenderten. Besonders
       index.html und den ganzen Ordner src/.
    2. Die Seite hart neu laden:
         iPhone/iPad:  Einstellungen > Safari > Verlauf und Websitedaten
                       loeschen. Oder die Seite einmal in einem privaten Tab
                       oeffnen.
         Android:      im Menue der Seite auf "Neu laden" lange druecken.
         Windows/Linux: Strg + Umschalt + R
         Mac:          Cmd + Umschalt + R
    3. Notfalls die Adresse mit einem Anhaengsel aufrufen:
         https://deine-domain.tld/mogli/?neu=1

  Ab Fassung 2.0.3 kann das eigentlich nicht mehr vorkommen: jede Code-Datei
  wird mit ihrer Versionsnummer angefordert, ein alter Eintrag im
  Zwischenspeicher wird also gar nicht mehr getroffen. In den Fassungen davor
  hing die Nummer nur an einer einzigen Datei - das war der Fehler.

  Zusaetzlich liegt eine .htaccess im Hauptordner. Sie
  sagt Apache, dass index.html nicht zwischengespeichert werden darf, und setzt
  fuer .js-Dateien den richtigen Typ - bei falschem Typ fuehrt kein Browser die
  Module aus, ohne einen Fehler zu zeigen. Bei nginx stehen die entsprechenden
  Zeilen als Kommentar in derselben Datei.

  Zeigt der Server nach dem Hochladen "Internal Server Error"? Dann erlaubt
  dein Hoster keine eigenen .htaccess-Regeln. Dann diese eine Datei loeschen -
  das Spiel laeuft auch ohne sie.

  GEHT ES IMMER NOCH NICHT? DIE PRUEFSEITE FRAGEN

  Im Paket liegt pruefung.html. Sie gehoert nicht zum Spiel und macht nur eines:
  sie prueft deinen Server von deinem Geraet aus durch und sagt im Klartext, was
  nicht stimmt.

      https://deine-domain.tld/mogli/pruefung.html

  Sie findet unter anderem: eine veraltete index.html auf dem Server, fehlende
  oder halb hochgeladene Dateien, einen falschen Datei-Typ fuer .js (dann fuehrt
  kein Browser das Spiel aus, ohne das zu sagen), fremde Skripte, die dein
  Hoster einhaengt, und ob PHP laeuft.

  Unten ist ein Knopf "Ganzen Bericht kopieren". Den Text einfach einfuegen und
  schicken - das sagt mehr als jede Beschreibung.

  Wenn schon pruefung.html nicht laedt (Internal Server Error): dann ist die
  .htaccess schuld, siehe oben. Loeschen, nochmal versuchen.

  Die Pruefseite danach wieder loeschen. Sie verraet nichts Geheimes, aber sie
  gehoert nicht auf eine Seite, die andere benutzen.

  Geht es trotzdem nicht, erscheint jetzt oben ein roter Streifen mit der
  Fehlermeldung. Diesen Text abfotografieren - darin steht, welche Datei fehlt
  oder wo es klemmt.

DATEIEN

  index.html        die Seite
  pruefung.html     prueft den Server, wenn etwas nicht laeuft; danach loeschen
  style.css         Gestaltung
  .htaccess         Servereinstellungen fuer Apache (verhindert alte
                    Zwischenspeicher-Staende); ohne sie laeuft es auch
  score.php         Bestenliste (optional)
  admin.php         Admin-Bereich (optional), hier ADMIN_CODE aendern
  assets.php        gibt die eigene Grafik an das Spiel heraus
  admin/            die Oberflaeche unter /admin
  data/             wird angelegt, gehoert nicht ins Backup
  src/              der Spielcode

  Sprache umschalten: oben rechts, DE oder EN. Die Wahl wird gemerkt.


ENGLISH
-------

INSTALL

  1. Unzip this archive into your webspace, e.g. /public_html/mogli/
  2. Open https://your-domain.tld/mogli/ in a browser.

  That is all. No database, no installation, no configuration.

IMPORTANT: DO NOT OPEN BY DOUBLE-CLICKING

  The game uses JavaScript modules, which browsers refuse to load over
  file:// for security reasons - double-clicking index.html shows a blank
  page. A web server is always required. To try it locally, run inside the
  unpacked folder:

      php -S localhost:8000
      python3 -m http.server 8000

HOW TO PLAY

  There is exactly one button: the playfield itself. Tap or click.

  1. Mowgli stands still until you tap for the first time. Only then does he
     start running, and only then does the ember start rising. You decide when
     it begins.
  2. He runs by himself. There is no direction key.
  3. Tapping jumps. Always the same height. There is no double jump.
  4. If he runs into a wall on the ground, he turns around by himself.
  5. When he slides down a wall, a tap pushes him off - and from then on he
     runs the other way. That is the heart of the game. You get exactly ONE
     wall jump per airtime; it comes back when you land and when a vine
     yanks you up.
  6. Emeralds score points. Vines yank him a good way upward.
  7. The ember rises from below. Stand still and it takes you.

  On a computer: Space jumps, P pauses, R restarts, M mutes, F is fullscreen.
  Gamepads are supported.

YOUR OWN GRAPHICS

  At /admin you can replace the sprites, tiles and background without
  touching any code: the character (eight animations, five frames each), the
  tiles and the background. The access code is 6713.

  SIZE AND FORMAT DO NOT MATTER

  Nothing needs cropping first. PNG, JPEG, WebP, GIF - whatever the browser can
  read, at any size. The admin area converts:

    - character -> 32 x 32
    - tile      -> 16 x 16
    - layer     -> large enough to cover the screen

  The aspect ratio is kept: a wide image is fitted, not squashed into a square.
  Whether it gets smoothed decides itself: if the ratio divides evenly
  (64 -> 32) the pixel edges stay crisp; if it does not (100 -> 32) it is
  smoothed, because otherwise whole rows would drop out. After each upload a
  line says what happened.

  A very tall background layer is cropped from the middle and shrunk further if
  needed - not on principle, but so the whole package still fits through your
  webspace's PHP upload.

  BACKGROUND: THE SPEED DECIDES EVERYTHING

    Speed 0     The image stands still. It fills the whole screen and is
                cropped from the middle where the aspect ratio does not match.
                This is the setting for a backdrop.
    Speed > 0   The layer scrolls while climbing. It is stretched to the game
                width and repeated vertically; its height says after what
                distance the pattern repeats. 1 moves with the tower.

  QUICKEST WAY: A GIF

  Next to every animation there is a GIF button. Drop an animated GIF there and
  it fills all five slots at once - no exporting single frames, no mixed-up
  order. The GIF must be 32x32.

    - more than five frames: five are picked by how long each one is shown, so
      a frame that rests gets more slots
    - fewer than five: they are spread over the five slots, none is dropped
    - what happened is reported right afterwards

  The GIF is taken apart in the browser; only the five separate PNGs are sent
  to the server. Single slots still take PNG.

  IMPORTANT, PLEASE CHANGE ONCE:
    - Set ADMIN_CODE in admin.php to a longer word. Four digits are 10 000
      combinations. There is a brake (five attempts per ten minutes), but a
      longer word is the only real protection. The line takes any string.
    - Set ADMIN_SALT in admin.php to any random text.

  The "Vorschau" tab runs a bot through your game with your images. If it
  cannot get anywhere, your collision boxes made the tower unclimbable.

  No PHP? Everything stays in your browser, and "Als Datei laden" gives you
  an assets.json to upload to data/ yourself.

WORLDWIDE LEADERBOARD

  If score.php is uploaded and PHP is enabled, all players share one
  leaderboard. It is stored in a plain file at data/scores.json - no database.

  To do:
    - data/ must be writable by PHP:  chmod 755 data
      Some hosts require 775 or a specific owner.
    - Change RATE_SALT at the top of score.php to any random text of your own.
      It keeps IP addresses stored as hashes only.

  No PHP, or data/ not writable? The game still runs completely. The
  leaderboard falls back to "This device only" and stores scores in the
  browser. The game shows which mode is active.

  On nginx the bundled data/.htaccess has no effect. Add to your server config:

      location ~ /data/ { deny all; return 404; }

  To keep scores outside the web root entirely, set the DATA_DIR constant in
  score.php to an absolute path.

UPLOADED A NEW VERSION AND IT LOOKS THE SAME?

  Or worse: the menu is there, but tapping "Los geht's" does nothing.

  That is almost always the browser cache. It kept the old index.html and
  loaded new code alongside it - or the other way round. The two no longer
  match, and the game sits silently in the menu.

  To do:
    1. Replace ALL files, not just the changed ones. Especially index.html
       and the whole src/ folder.
    2. Hard-reload the page:
         iPhone/iPad:  Settings > Safari > Clear History and Website Data.
                       Or open the page once in a private tab.
         Android:      long-press "Reload" in the page menu.
         Windows/Linux: Ctrl + Shift + R
         Mac:          Cmd + Shift + R
    3. If all else fails, call the address with a suffix:
         https://your-domain.tld/mogli/?neu=1

  From version 2.0.3 on this should not happen any more: every code file is
  requested with its version number, so a stale cache entry can no longer be
  hit. In earlier versions the number was attached to a single file only - that
  was the bug.

  In addition, an .htaccess sits in the main folder. It tells
  Apache not to cache index.html, and sets the correct type for .js files - with
  the wrong type no browser executes the modules, and none of them says so. The
  nginx equivalent is a comment in the same file.

  Server showing "Internal Server Error" after the upload? Then your host does
  not allow custom .htaccess rules. Just delete that one file - the game runs
  without it.

  STILL NOT WORKING? ASK THE CHECK PAGE

  The package contains pruefung.html. It is not part of the game and does one
  thing only: it checks your server from your own device and says in plain words
  what is wrong.

      https://your-domain.tld/mogli/pruefung.html

  It finds, among others: an outdated index.html on the server, missing or
  half-uploaded files, a wrong file type for .js (no browser executes the game
  then, and none of them says so), foreign scripts injected by your host, and
  whether PHP runs.

  There is a "Ganzen Bericht kopieren" button at the top - paste that text and
  send it. It says more than any description.

  If pruefung.html itself does not load (Internal Server Error), the .htaccess is
  to blame, see above. Delete it and try again.

  Delete the check page afterwards. It gives away nothing secret, but it does not
  belong on a page other people use.

  If it still fails, a red bar now appears at the top with the error message.
  Photograph that text - it says which file is missing or where it breaks.

HONESTLY

  Scores are computed in the player's browser. Anyone can send a made-up
  number with a single command-line call. score.php rejects implausible
  values, rate-limits per IP and strips HTML from names - but none of that
  stops someone determined. The list is for fun, not for records.
